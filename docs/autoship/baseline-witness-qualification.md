# Original baseline witness qualification

Autoship must establish a production defect before it admits a builder. A
pinned program producing different output on two revisions is insufficient:
the original revision might have selected no tests, while candidate-owned tests
produce the expected success markers.

The raw contract comparator still compares measured data. A separate protected
native judgment qualifies the measurement path before enrollment, builder
binding and shipping. This does not replace candidate verification, alignment,
independent final review or GitHub checks.

## Qualification inputs

The qualification context binds the original Git base, complete registered
proposal and pinned harness contents, every criterion and verifier, measured
baseline receipts, and current controller policies. Receipt output digests bind
the complete captured output. Existing diagnostic strings are bounded previews;
they must not be represented as full observations.

The independent native session must cover each verifier and all its associated
criterion IDs. A positive judgment requires an available original fixture,
concrete inputs, direct production observations, and exact citations from
regular files in the immutable original Git tree. New harness files and
candidate-only fixtures cannot serve as original production source citations.
The native judge must return unknown when the available source and diagnostics
do not support attribution to production.

JSON, text and boolean production observations remain supported. Child test
assertions, discovery, summaries, setup errors and success markers do not become
production observations because their launcher was pinned.

The controller retains the exact native response and provenance privately.
Native reasons and source quotations stay in that evidence; general error
surfaces use fixed classifications. The authority directory is checked through
its effective owner-controlled boundary: ordinary umask-created descendants
may be group-writable beneath an owner-only state root. Exposed writable paths,
foreign ownership, candidate/build write roots and changed or missing private
proof still refuse admission. Qualification is an independent native
judgment. It grants no implementation changes, final-review approval or merge
permission.

## Recovery and accounting

The successful original measurement is retained before qualification can spend
a model call. Restart reuses that measurement rather than creating another
qualification input from changed compiler diagnostics or timing.

Completed native replies and provenance are retained before the successful
native review scope is retired. Cached original and correction replies bind
the exact request and policy. A completed reply can be recovered when its
provider is unavailable; saved source selections remain immutable Git data.

An admitted witness call without its original completed evidence blocks new
model admissions, including builders, other reviewers and amendments. Late
usage accounting for the original call remains allowed. A capacity refusal
before admission retains its actual cause and does not become a claim that a
native result was lost. These paths reuse existing workflow leases, response
storage, model accounting and bounded correction/amendment budgets.

## Existing workflows

Existing valid baseline evidence can receive a separate qualification receipt.
An invalid verifier must use the existing independent amendment authority,
preserving its original base, criteria, observations, expenditure and candidate
edits. Qualification failures on enrolled work retain that exact registration,
binding and evidence while recording their typed private hold. They do not use
the stricter unenrolled initial-scope mutation. Held attempts report actual
admitted model calls through the existing accounting path. A replacement verifier needs its own original-baseline measurement and
qualification. A recovery-only identity binding cannot authorize a builder.

Builder binding checks the canonical workflow source, including issue workflows
accessed through a PR alias. Model admission rechecks the retained qualification;
an earlier in-memory success does not excuse missing or modified evidence.
The final shipping path and merge sweep require current qualification even when
an older receipt and approval have valid hashes.

Inspect a workflow through the supported command:

```sh
augmentagent autopr status --workflow 'owner/repo#123' --json
```

Do not repair workflow state by editing SQLite, replacing private receipts or
resetting counters. Full failed-result custody and failure-path runtime
retirement remain tracked in [#1952](https://github.com/nolanmak/Jarvis/issues/1952).
The baseline defect and its test-first recovery are tracked in
[#2030](https://github.com/nolanmak/Jarvis/issues/2030).

Engineering repair PRs are merged through ordinary review and CI. Restoration
is proved by autoship completing ordinary issues; manual repair merges do not
count as autonomous merges.
