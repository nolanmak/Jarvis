# Native inventory and pending-request preparation

This amendment extends `1713-native-owner-transfer-design.json` for the physical-inventory boundary. It does not enable a productive consumer or close #1703. The existing CLI/Discord/native-session/rollout/soak, C freshness/storage cleanup and private-verifier requirements remain binding. The core owns physical native state; the workflow store owns commands, candidate bindings, immutable observations, pending requests and settlement. No new workflow engine or second native-state authority is introduced.

## Decisions

I1. A workflow history snapshot is a metadata projection. Its rows are not proof that a runtime remains retained. Reconcile every latest launch/observation with the original bound native store before persisting a new transfer request. A nullable ID or uncertain outcome remains unknown for a retained runtime. A verified retirement can remove that runtime from the selected retained set; it never rewrites its old observation as successful. Owners with zero retained runtimes remain in the source-registration set and still require healthy audit closure.

I2. Use the original `TransferBinding`, canonical store identity and current workflow/candidate/active-pending fences. A selected-policy mismatch, replaced/missing original authority or invalid schema cannot be repaired by initializing a new store. Reuse the core's existing private-file checks, effective-owner resolver, alias/export verifier, state lock, session locks, bounded ledger and typed outcomes. Read-only bound-store scan/validation may precede workflow intent; D7's older “pending before external I/O” wording is narrowed here to native ownership/prepare/seal mutation, not this read-only inspection. No read-only stage may bootstrap authority. All native I/O runs outside the workflow mutex/SQLite transaction; a bounded metadata callback can take that mutex while the native state lock is held.

I3. Preparation is one synchronous core orchestration, not an unlocked scan followed by a workflow write. Hold the original native `StateLock` while scanning, acquiring every relevant existing session lock, verifying retained/retired partitions, invoking the workflow persistence callback, and installing the exact request's existing ledger claims with `Ledger::prepare`. Refactor the existing handoff implementation to accept this already-held lock/ledger; do not recursively acquire the state lock. Keep the relevant session locks through prepare and the existing seal/commit sequence. The callback atomically captures/revalidates authoritative latest workflow inputs, persists the filtered immutable snapshot and exact pending request, and returns that persisted request/observation. The core verifies they equal its scan/source/destination/binding inputs before preparing claims. Native mutation still follows durable workflow intent. If callback persistence fails, no native prepare, source seal or ownership mutation is permitted.

I4. Physical classification enumerates all four known provider directories (codex, claude, qwen, glm), with at most 4,096 total directory entries and 4,096 session directories per attempt, including foreign and retired entries; exceeding either limit returns StateCapacity before workflow/native mutation. Owned/marker/alias metadata reads total at most 64 MiB. Retired entries count against scan work, not the transfer's 64 retained-session limit. Retained export hashing retains D2's per-generation limits (64 MiB, 4,096 files, 2,048 directories). Incomplete enumeration never proves absence or certainty. Classification reads the entire workflow-owned namespace within those bounds, including paths absent from the supplied candidate list. Resolve actual creation/effective authority through the bound ledger. Refuse unknown live runtimes, path/creation substitutions, aliases/exports that do not match the latest certain observation, active session locks, unsupported providers, and incomplete source registrations. A retained unknown-ID/uncertain launch is a hold, not an omitted row. Check current authority and original store identity before the scan, before workflow persistence, before native prepare, every source seal and commit. The core transfer remains the final physical inventory and kernel-quiescence verifier.

I5. Retirement markers need provenance, not only `version == 1`. Ordinary scope retirement remains supported by native_vm::retire (including NativeSession/Launch Drop), distinct from controller-authorized retire_owned_runtimes. Its existing captured-owner/store and unclaimed-owner/runtime/audit checks under StateLock remain mandatory. It writes a strict version-2 marker {version:2,reason:"native_scope_retired",authority:Authority,runtime_relative_path:string,creation_receipt_sha256:lowercase64,store_identity_sha256:lowercase64}. Authority uses the shared owner/audit wire type; store_identity_sha256 hashes canonical_bytes(original StoreIdentity), including its epoch. Capture creation/path provenance when the retirement entry is registered, then verify it again before writing; do not adopt a replacement by re-reading it as a new expected value. NativeSession/Launch Drop never creates owner closure or aborts a pending transfer. The separately authorized controller retirement path keeps its owner-retirement marker and ledger proof. Owner-retirement markers must match the current effective owner/audit and an actual `retired_owner` ledger record; transfer closure is not retirement. Legacy ownerless scope markers, vanished recorded runtimes and unknown marker formats cannot silently supply this new proof. Retain their history and hold the affected namespace for existing authenticated retirement/recovery. Do not infer retirement from a missing file, elapsed time, process ID, or a creator whose ownership already transferred. The same original-bound marker-provenance validator must gate both transfer classification and root-wide prune_and_count, including runtimes from other workflows sharing the state root. Reclamation additionally requires its existing available session flock and completion/retention predicates. Malformed, legacy-unproven, foreign-owner and stale-store markers retain runtime/alias/export bytes; parseable JSON alone never authorizes deletion. Passing the already-open bound ledger to pruning must not reopen/bootstrap another authority. Both consumers must migrate before activation, with cross-workflow pruning regressions. No source/export deletion is added here.

I6. A crash can occur after workflow pending commit but before `Ledger::prepare`; locks alone do not survive it. Reconcile that exact UUID in the original store before any replacement request. Completed uses existing verified-receipt settlement; Prepared keeps the original request/claims and existing recovery; Aborted follows I9 below, distinct from corrupt/Unknown state; Unknown never authorizes replacement. For an exact known-Absent request, a core operation holds the original state lock while invoking an acknowledgement callback under a current reconciliation lease newer than the pending destination, or the exact terminal-checkpoint cleanup fence described below. The callback revalidates the original pending record, stores an immutable known-unstarted disposition, and acknowledges that pending record atomically. No ownership, source audit or paid accounting changes. All production transfer-current callbacks must validate the exact active pending UUID/input digest, as well as the reconciliation lease/candidate, immediately before `Ledger::prepare` and every later side effect. Thus a late older controller is fenced by its lease, and a waiting same-request call is fenced by pending acknowledgement before the state lock is released. A generic `transfer_receipt() == None` is insufficient: it currently conflates Prepared with Absent. The absence capability is private/nonserializable and created only by that original-store state inspection while the lock remains held. No free-standing boolean or unlocked absence result may acknowledge a request. For terminal known-Absent reconciliation, the callback instead validates the unchanged Merged/Retired checkpoint identity (workflow, terminal generation, canonical checkpoint hash and its terminal event sequence) plus the original pending record. It stores known-unstarted history and acknowledges that record in one transaction, preserves all registered-source cleanup intents/barriers, creates no unproven destination owner/binding and no productive lease, and never schedules a replacement transfer. If cancellation/checkpoint identity changes before acknowledgement, retain the original intent and retry the exact terminal path. Missing/unreadable terminal authority remains Unknown/held.

I7. Workflow preparation must reconcile an existing pending record before capturing another snapshot/UUID. A newer reconciliation lease can settle an older completed destination without dispatch; if generations differ, it prepares the next handoff into a distinct current audit namespace. Successful metadata settlement is not productive promotion. Terminal/namespace cleanup-only settlement and original owner intent remain separate mandatory paths; no pending acknowledgement completes an owner message, clears a pause or grants a review/merge receipt.

I8. Failure/retry remains free reconciliation under the epic's existing cadence/backoff. Persist original UUID, source/candidate/binding, latest-row fingerprints and disposition before clearing an intent. Retain original budgets, baseline and owner intent. Selected-policy or inventory changes can wake a retry but cannot overwrite an in-flight request. Existing SourceLock/native ledger claims and cleanup retention stay authoritative; do not create a host cache, a new credential grant or a parallel reservation scheme.


I9. For an exact Aborted request, original-store inspection under StateLock produces an opaque abort disposition binding the original request/observation/store and each source/destination namespace. A current reconciliation lease (or the separate exact terminal-checkpoint cleanup fence) acknowledges it in one workflow transaction: persist immutable known-aborted history and original pending sequence; persist a per-namespace unresolved barrier for every affected source and the unpromoted destination; record any already verified namespace resolution; then clear the active pending row. This does not synthesize a completed transfer receipt or transferred-source disposition. A barrier resolves only through existing authenticated terminal/per-namespace retirement or audit recovery with the same original binding and exact namespace plus correlated kernel-quiescence evidence; native retired_owner alone is not process teardown. Retired/migrated/unpromoted namespace metadata is preserved without granting productive dispatch. All shared preparation/promotion entry points refuse while any barrier remains unresolved, and status names the required namespace recovery. Remaining peers are never implicitly retired because one source caused abortion. Once every barrier is resolved, normal source reconciliation/selection can prepare a new UUID under a new lease without changing historical outcomes, budgets or owner input. If the original aborted authority cannot be read/validated, keep Unknown and the active intent; this known-abort acknowledgement cannot repair corrupt native prepared state.


I10. The version-1 source-registration hash uses the bare JSON array already implemented by the workflow store: canonical_bytes([{source:Authority,original_binding:TransferBinding,registration_sequence:positive_integer}, ...]), SHA-256 lowercase64. Sort registrations by ascending lease_generation, then audit_path UTF-8 bytes; include every eligible registered source, including zero-runtime owners, with its immutable original binding and original registration event sequence. There is no additional envelope in this version; the containing snapshot's version selects this projection. Completed-transfer disposition determines eligibility but never changes historical registration bytes. The complete version-1 NativeObservation projection also includes launch_intent_id (canonical nonnil UUID string), linking the exact protected launch journal; this field is hashed with all the other declared row fields. These definitions amend the JSON observation_contract where it previously left the registration projection implicit or omitted launch_intent_id. Do not silently rewrite an existing pending observation hash or snapshot to the latest definition.


I11. Before pending persistence, preparation returns a distinct no-pending result: Deferred(reason,fingerprint) for transient contention/capacity or Held(reason,fingerprint) for provenance/authority uncertainty. It carries phase=preparation and no transfer UUID, positive snapshot revision, or receipt claim. Never invent those values to satisfy the existing transfer-outcome API. The stable retry key is workflow + native_handoff_preparation; add that finite domain value to the existing per-failure retry service rather than creating another retry ledger. Fingerprint is lowercase SHA-256 of canonical_bytes({version:1,workflow_id,workflow_binding,original_binding_sha256,source_registration_sha256,latest_input_sha256,selected_policy_sha256,reason_code,failure_class,capacity_class}). Unknown/unavailable input digests are explicit null, never guessed; latest_input_sha256 hashes canonical_bytes of the complete unfiltered array [{provider:codex|claude,runtime_relative_path,latest_launch:complete NativeLaunchRecord,latest_observation:complete NativeObservation|null},...], one entry per latest launched physical runtime, sorted by provider then runtime path UTF-8 bytes, and source_registration_sha256 uses I10. capacity_class is exactly {free_gib,reserved_mib,history_mib}; each value is null when unobserved, otherwise floor available-bytes/GiB, reserved-bytes/MiB and history-bytes/MiB respectively, matching existing core classification. Exclude clock, PID, retry attempt, provisional destination audit name and reconciliation lease generation so restarts do not create meaningful-input changes. Persist through the existing per-failure retry service: 5/10/20/40/60-minute capped backoff, reset/wake only for actual fingerprint changes, no model/merge allowance charge. Once the callback commits pending intent, all failures switch to the exact stored UUID/observation/binding and existing bound transfer reconciliation. There is no path back to no-pending merely because a receipt is unavailable.

## Failure and replay exits

- Before workflow persistence: no new pending/native mutation; retry after the actual blocker changes.
- Workflow write failure: transaction rolls back snapshot, pending event and record; no native prepare/seal.
- Crash after workflow persistence, before native prepare: exact original-store inspection; only exact known-Absent under I6's locked newer-lease or exact terminal-checkpoint callback can acknowledge that request's metadata. Only the nonterminal newer-lease path can subsequently allow re-preparation; terminal cleanup never does.
- Crash after native prepare or a source seal: existing claims and UUID retained; no new request or deletion; existing prepared/partial-seal recovery applies.
- Native commit before response or workflow acknowledgement: original-ledger receipt lookup and existing atomic settlement.
- Same-policy path resolving to another store, missing authority, corrupt schema/claims, or unavailable fence: typed Unknown/Held with original identity, no initialization or acknowledgement.
- Runtime retires during preparation: the state/session locks serialize it with scan/persistence/prepare. After claims exist, ordinary scope retirement/Drop cannot abort the request; controller-authorized fenced retirement retains D10's atomic abortion path. If the process crashes before claims, use the exact known-Absent replay above.
- Old controller wakes during known-Absent acknowledgement: it cannot acquire the state lock until the callback commits; its required active-pending/lease fence then refuses prepare. Test this actual ordering, not a mocked success boolean.

## Open threads and accepted limits

O1: The native controller owner implements authenticated recovery for legacy ownerless scope markers and vanished recorded runtimes. Trigger: the census/scan finds them. Carrying cost: affected namespaces stay held with original history/budgets; no guessed tombstone or new origin. This blocks their live admission, not writing new provenance-carrying markers now.

O2: The caller owner must prove lock ordering for late launch/observation callbacks versus state-lock preparation and anchored audit seals. Trigger: implementing the shared callback/core refactor. Existing store-to-audit receipt reads must not deadlock with audit-seal-to-store current checks. This is an enablement blocker and requires real concurrent tests; no claim that merely using `&mut` makes cross-process mutation impossible.

Accepted temporary cost: preparation may perform repeated bounded physical verification and reject a busy namespace. End condition is verified reconciliation, not increasing timeouts or bypassing session locks. No final handoff-readiness or production restoration claim is made by this document.

## Glossary

Metadata snapshot: immutable workflow projection, not physical retention or quiescence. Retained runtime: original-store session eligible for continuation with verified current authority and completion. Retired runtime: proven ended authority, never a successful replacement observation. Known-Aborted disposition: exact original ledger abort plus durable per-namespace barriers, not completed ownership transfer. Known-Absent request: exact UUID absent from the original valid ledger under the held state lock, distinct from an unreadable store or an existing Prepared request. Metadata acknowledgement: durable local reconciliation; not native ownership mutation, owner-message completion or productive promotion.
